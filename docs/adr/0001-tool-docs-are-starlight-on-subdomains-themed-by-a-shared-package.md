# ADR-0001: Tool documentation is Starlight on per-tool subdomains, themed by a shared package

## Status

Accepted, 2026-09-13. First ADR in this repo; this repo exists because of it.

## Decision

**Each published tool keeps its own documentation site on its own subdomain** — `auberge.espadat.com`, `dublette.espadat.com`, `colporteur.espadat.com` — served from its own repo's GitHub Pages.

**The substrate is Astro Starlight, not docsify and not mdBook.** The Astro project lives at `<repo>/docs/`, with content under `docs/src/content/docs/`.

**The visual identity ships from this repo as a versioned git dependency**, not as vendored copies and not via npm: `"@espadat/docs-theme": "github:espadat-studio/docs-theme#vX.Y.Z"`.

**Existing URLs are preserved exactly.** The curated sidebar is hand-translated to explicit Starlight config rather than autogenerated from the directory tree.

**The sites are light-only.** Starlight's theme toggle is suppressed.

**The roster is frozen at three.** `pi-memsearch` gets no site. `etiquette` never inherits this theme — it is a separate product brand.

**`meta/` holds material that is not published; `docs/` holds material that is.** This was incidental before and is load-bearing now that `docs/` is a build directory.

## Why

### Why not mdBook

This is the decision a reader will question first, and the one most likely to be "fixed" by someone later. Three Rust crates now each carry a Node toolchain to build their documentation, which looks like an oversight. It is not.

The sites are studio design evidence, not only reference material. `espadat.com` points at them as the only web design work showable without client permission. mdBook themes via handlebars overrides and CSS injection; Astro is already the studio's stack, so `tokens.css` is *imported*, not re-expressed. That difference is the whole argument: a hand-translated design system in three repos drifts, and the thing being demonstrated is cross-host consistency.

### Why not keep docsify

Repainting docsify was the cheaper path and was seriously considered. Two things decided against it.

Docsify renders client-side, so **108 pages of auberge documentation are invisible to search engines** — the designated proof artifact for the self-hosting service, undiscoverable. And styling docsify means writing override rules against `vue.css`'s selectors: a translation of the design system, per repo, that nothing keeps honest.

### Why subdomains and not `espadat.com/tools/<name>`

GitHub Pages binds one custom domain per repo. Path routing would need either a proxy in front of the apex, or the docs consolidated into one repo — and consolidation breaks **docs-ship-with-the-release**. `auberge` releases via release-plz and its documentation is versioned with the crate; docs that drift from the binary are worse than plain docs.

The SEO argument for subfolder consolidation is real in general and worth approximately nothing here, where referrers are GitHub and crates.io.

### Why a git dependency and not npm

A published package and a tagged git dependency both give one canonical copy with semver pinning. npm additionally costs an org, a publish workflow and a release discipline, to serve three consumers owned by the same person. The package is CSS plus two `.astro` files, which Astro compiles in the consumer, so skipping the registry loses no build step.

**The dependency must live in its own public repo**, not inside `espadat.com`, which is private — three public repos cannot depend on a private one and still be cloneable.

Vendoring was the first recommendation and was rejected once the consumer count was fixed at three: the same drift argument that rules out hand-translated CSS rules out hand-copied CSS.

### Why light-only

`espadat.com/src/styles/tokens.css` commits to one light world on purpose: the palette is an Admiralty chart, and a printed chart does not invert. Adding dark mode means inventing an inverted chart palette that exists nowhere, with its own contrast audit, and then keeping two worlds honest.

This is the decision most likely to annoy the primary audience — developers reading long reference pages expect a theme toggle, and its absence reads as an oversight rather than a choice. Recorded here so it is not "fixed".

### Why URLs are preserved and the sidebar is hand-written

Starlight can autogenerate a sidebar from the directory tree. auberge's `_sidebar.md` deliberately groups across directories — `core-concepts/architecture.md` is filed under *Getting Started* — and autogeneration discards that editorial judgement.

Restructuring during a framework migration would change every internal link on top of the extension rewrite and require a redirect table. One thing at a time.

## What it costs

- **A Node toolchain in three Rust repos.** New `package.json`, new build step, new Pages workflow, and `build_type` flips off `legacy` in each.
- **Starlight is pre-1.0** (0.42.0, peering `astro: ^7.2.10`). Breaking changes land. Renovate on all three consumers is what makes this survivable, and two of them have no renovate config today.
- **133 files move and change.** Every page gains `title:` frontmatter; internal links lose their `.md` extensions. Mechanical, with a long tail.
- **`docs/` stops meaning "documentation" and starts meaning "the documentation site project".** Internal material belongs in `meta/`. `pi-memsearch` keeps `docs/adr/` and `docs/agents/` because it publishes nothing.
- **16 hash-routed deep links** across three READMEs break and are rewritten by hand. No redirect shim: zero such links exist outside those READMEs.

## Alternatives considered

- **mdBook.** The Rust-native default. Rejected: theming is the point, and Astro is the studio's stack.
- **Repainted docsify.** Cheaper. Rejected on client-side rendering and per-repo style translation.
- **Starlight for auberge only, docsify repaint for the small two.** Rejected: two implementations of one design system is the exact inconsistency a buyer grades down.
- **Path routing via a Cloudflare Worker, or one aggregator repo.** Rejected: breaks docs-ship-with-the-release; buys SEO that does not apply.
- **npm-published theme package.** Rejected: registry machinery for three first-party consumers.
- **Vendored theme files.** Rejected: silent drift, the same failure as hand-translated CSS.
- **Keeping markdown at `docs/**/*.md` with the Astro project elsewhere.** Rejected: Starlight's `docsLoader()` takes only `{ generateId }` and resolves `src/content/docs/` from the project root. Preserving a directory name is not worth bypassing it for a raw `glob()` loader.
- **Dark mode on the docs sites only.** Rejected: an inverted chart world with no tokens and no audit.
- **A site for `pi-memsearch`.** Rejected: that is content work, not theme work. `studio.ts` already states the three-of-four asymmetry without apology.
- **`etiquette` inheriting this theme.** Rejected by an existing brand commitment: separate product brand, footer credit only.
